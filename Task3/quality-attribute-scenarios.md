# Quality Attribute Scenarios

> NFR-xx — [реестр НФТ](nfr-registry.md); паттерны защиты — [fmea.md](fmea.md). Источники А1–А7 — [входные материалы](../artifacts/README.md).

## QAS-01. Доступность: отказ зоны доступности в пике

| Поле | Значение |
|---|---|
| Источник | Инфраструктура облачного провайдера |
| Стимул | Зона доступности с primary PostgreSQL и частью узлов K8s перестаёт отвечать |
| Артефакт | Оформление заказа и оплата (модули «Заказы», «Платежи»), PostgreSQL |
| Среда | Флеш-распродажа, 300 заказов/мин |
| Отклик | Автоматический failover PostgreSQL на standby в другой зоне; K8s перезапускает поды в оставшихся зонах; приложение повторяет запросы к БД с backoff; заказы, начатые до сбоя, завершаются по идемпотентному ключу |
| Мера отклика | RTO ≤ 2 мин, RPO = 0, 0 потерянных и 0 задвоенных заказов; простой укладывается в бюджет 21,6 мин/30 дней (NFR-01, NFR-09) |

## QAS-02. Доступность: отказ платёжного провайдера

| Поле | Значение |
|---|---|
| Источник | Flutterwave (Нигерия) или M-Pesa Daraja (Кения) |
| Стимул | 50% запросов к провайдеру завершаются 5xx или таймаутом > 3 с в течение 2 мин |
| Артефакт | Адаптер платёжного провайдера |
| Среда | Обычная нагрузка, вечерний пик |
| Отклик | Circuit breaker размыкается; новые оплаты в Нигерии уходят в Paystack, в Кении — картой через Flutterwave; если резервного пути нет, заказ сохраняется со статусом «ожидает оплаты», а покупатель получает ссылку на оплату. Периодически отправляются пробные запросы к основному провайдеру, после восстановления цепь замыкается |
| Мера отклика | Переключение ≤ 30 с; 100% заказов сохранены; доступность оформления ≥ 99,95% за 30 дней; алерт SEV2 через 5 мин (NFR-11) |

## QAS-03. Задержка P99: каталог при рекламном пике

| Поле | Значение |
|---|---|
| Источник | Покупатели, открывшие приложение после радиоролика (А2) |
| Стимул | Рост нагрузки на каталог со 170 до 1 000 RPS за 5 мин |
| Артефакт | API каталога и поиска, Valkey, PostgreSQL |
| Среда | День запуска, 3G/4G у клиентов |
| Отклик | Листинги отдаются из CDN, карточки — из Valkey (cache-aside); одновременные промахи по одному ключу сводятся к одному запросу в БД; HPA добавляет реплики по RPS |
| Мера отклика | P99 ≤ 500 мс и P95 ≤ 300 мс на ingress; попадания в Valkey ≥ 90%; первый товар на экране ≤ 2 с для 90% холодных запусков (NFR-04, NFR-05) |

## QAS-04. Пропускная способность: флеш-распродажа

| Поле | Значение |
|---|---|
| Источник | Покупатели во время таймера распродажи (А2) |
| Стимул | 300 оформлений заказа в минуту в течение 15 мин, 20% из них — на одни и те же 50 SKU |
| Артефакт | Модуль «Заказы», резерв остатков, очередь |
| Среда | Пиковая нагрузка, каталог 1 000 RPS параллельно |
| Отклик | Остаток резервируется атомарно в PostgreSQL; отдельный пул соединений для оформления заказа (bulkhead) защищает его от нагрузки каталога; уведомления и создание отправлений уходят в очередь; лимит запросов на одного клиента |
| Мера отклика | 300 заказов/мин при P99 ≤ 1,5 с; 0 продаж сверх остатка; ≤ 1% ответов 429 и 503; возраст сообщений в очереди ≤ 30 с (NFR-06, NFR-08) |

## QAS-05. RTO/RPO: потеря региона

| Поле | Значение |
|---|---|
| Источник | Облачный провайдер (авария региона) или ошибка оператора |
| Стимул | Основной регион недоступен дольше 30 мин, прогноз провайдера не дан |
| Артефакт | Вся платформа, кроме хранилища ПДн в Нигерии |
| Среда | Рабочие часы или ночь, дежурит один инженер |
| Отклик | Дежурный объявляет SEV1, CTO принимает решение о переключении. По runbook: асинхронная реплика PostgreSQL во втором регионе становится основной, кластер разворачивается из Git через Terraform и ArgoCD, DNS переключается. Приложение всё это время показывает каталог из кеша |
| Мера отклика | RTO ≤ 4 ч, RPO ≤ 5 мин; заказы, потерянные в окне RPO, восстанавливаются сверкой с выписками провайдеров (NFR-10) |

## QAS-06. Релиз без простоя

| Поле | Значение |
|---|---|
| Источник | Команда разработки |
| Стимул | Выкатка версии, которая поднимает долю 5xx на оформлении заказа до 3% |
| Артефакт | Модульный монолит, конвейер ArgoCD |
| Среда | Рабочий день, обычная нагрузка |
| Отклик | Rolling update; readiness-проба не пускает трафик на неготовые поды; алерт по расходу бюджета ошибок запускает автоматический откат на предыдущую версию из Git |
| Мера отклика | Откат ≤ 10 мин; израсходовано не больше 5% месячного бюджета PAY-SLI-1; 0 ручных изменений в кластере (NFR-12, NFR-14) |

## Assumptions

- Пик в 1 000 RPS и 300 заказов/мин — расчётные цели из реестра НФТ (раздел Assumptions). Их нужно подтвердить нагрузочным тестом до 01.10.
- Решение о переключении региона принимает CTO, потому что переключение с RPO ≤ 5 мин может потерять заказы. Автоматическое переключение региона в MVP не делается.
