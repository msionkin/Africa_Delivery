# План отказоустойчивости и переключения

**Дата:** 2026-08-28 · **Статус:** Предложено; первые DR-учения — до 01.10, далее раз в квартал

> Размещение — [ADR-003](adr-003-data-residency.md), схема — [deployment-diagram.png](diagrams/deployment-diagram.png). Цели: NFR-09 (отказ зоны: RTO ≤ 2 мин, RPO = 0) и NFR-10 (отказ региона: RTO ≤ 4 ч, RPO ≤ 5 мин) из [nfr-registry.md](../Task3/nfr-registry.md); виды отказов F-07, F-11 и F-12 — из [fmea.md](../Task3/fmea.md).

## 1. Решение по высокой доступности

| Уровень | Как обеспечено | Переключение |
|---|---|---|
| Под или узел | GKE regional, ≥ 2 реплики приложения в разных зонах, PodDisruptionBudget (при обновлении узлов поды останавливаются по одному) | Автоматически, секунды |
| Зона GCP | Cloud SQL HA со standby в другой зоне; Memorystore Valkey с репликой; балансировщик на 3 зоны | Автоматически, ≤ 2 мин, RPO = 0 |
| Регион GCP или весь GCP | Тёплый резерв в AWS af-south-1: RDS PostgreSQL — подписчик логической репликации, S3 с копией объектов, зеркало образов в ECR. EKS разворачивается из Terraform при переключении | Вручную по решению CTO, ≤ 4 ч, RPO ≤ 5 мин |
| Узел NG (Layer3 Лагос) | Реплика PII-хранилища и снимки OpenBao в Абудже; circuit breaker в ядре | Вручную, ≤ 4 ч, RPO ≤ 5 мин |
| DNS | Route 53 у DR-провайдера, TTL 60 с, health check на синтетику | Автоматически убирает недоступный узел NG; переключение региона — вручную |
| Партнёры | Второй платёжный провайдер на страну, очередь отложенных уведомлений (FMEA) | Автоматически |
| Мониторинг | Grafana Cloud вне ЮАР; синтетика из Лагоса и Найроби | Не зависит от отказа региона |

## 2. Кто принимает решение

| Роль | Решает |
|---|---|
| Дежурный инженер | Объявляет SEV1, запускает runbook отказа узла NG и начинает подготовку DR: создаёт EKS, это ничего не переключает |
| CTO (или заместитель CTO) | Переключает регион и возвращает работу в основной регион. При переключении могут потеряться заказы в окне RPO, поэтому решение принимает CTO |
| CEO | Информирует инвестора, продавцов, публикует статус в приложении |
| DPO | Оценивает, не было ли утечки; уведомляет NDPC или ODPC в течение 72 ч, если ПДн затронуты |

## 3. Сценарии

### S1. Потеря зоны GCP

Действует автоматическое переключение (QAS-01). Ручных шагов нет. **Время:** ≤ 2 мин. **Потери данных:** 0.

### S2. Потеря региона GCP africa-south1 или глобальный сбой GCP

**Триггер:** синтетика из Лагоса и Найроби фиксирует отказ дольше 30 мин, провайдер не даёт прогноза.

| Время | Шаг |
|---|---|
| T+0 | Алерт, дежурный объявляет SEV1. Приложение показывает каталог из кеша, заказы копятся в офлайн-очереди |
| T+0–30 | Диагностика. Параллельно `terraform apply` создаёт EKS и ElastiCache в af-south-1: подготовка обратима и ничего не переключает |
| T+30 | **CTO решает о переключении** |
| T+30–60 | Логическая репликация останавливается, RDS становится основной БД. Фиксируется последний применённый LSN |
| T+60–150 | ArgoCD разворачивает приложение из Git, образы берутся из ECR. Конфигурация переключается на адаптеры AWS: SQS, S3, AWS KMS |
| T+150–210 | Смоук-тесты: вход по OTP (NG — через узел NG, не затронут), заказ в тестовом режиме, вебхуки партнёров. Исходящие IP DR заранее внесены в allowlist партнёров |
| T+210–240 | В Route 53 `api.*` и CDN переключаются на AWS (CloudFront). Узел NG перенаправляет VPN на AWS |

**Время:** ≤ 4 ч. **Потери данных:** ≤ 5 мин записей ядра. Утерянные заказы и платежи восстанавливаются сверкой с выписками Flutterwave, Paystack и M-Pesa по нашему reference. ПДн NG не затронуты: они в Лагосе. ПДн KE и ZA есть в RDS, и их можно расшифровать ключом AWS KMS.

**Возврат в основной регион:** после восстановления GCP запускается обратная логическая репликация RDS → Cloud SQL. Переключение — в окно минимальной нагрузки, по решению CTO, в течение 2 недель.

### S3. Отказ узла NG (Layer3 Лагос)

**Триггер:** health-check PII-API и синтетика из Лагоса не проходят дольше 15 мин.

| Время | Шаг |
|---|---|
| T+0 | Circuit breaker в ядре: каталог и корзина работают, активные сессии держатся на JWT. Новые входы нигерийцев, оформление доставки и уведомления NG встают в очередь (outbox) |
| T+15 | SEV1, запрос в поддержку Layer3 |
| T+60 | **CTO решает переключиться на Абуджу**, если Layer3 не даёт прогноз |
| T+60–180 | Реплика PostgreSQL в Абудже становится основной. OpenBao восстанавливается из снимка, держатели ключей распечатывают его (3 из 5). ArgoCD разворачивает узел NG в K8s Абуджи |
| T+180–240 | VPN из GCP переключается на Абуджу, Route 53 — на `ng.api.*`. Очередь уведомлений отправляется |

**Время:** ≤ 4 ч. **Потери данных:** ≤ 5 мин изменений профилей и согласий NG. Заказы не теряются: они в ядре. Данные из Нигерии не выходят ни на одном шаге.

### S4. Отказ DR-площадки AWS

Пользователи ничего не замечают. Алерт по `replication_lag_seconds` > 300. Восстановить репликацию — в течение 24 ч; до восстановления защита от S2 ослаблена, CTO об этом информируется.

### S5. Разрыв связи ЮАР ↔ Нигерия (подводные кабели)

Нигерийские покупатели теряют доступ к ядру. Приложение работает на кеше, заказы ждут в офлайн-очереди. Ядро ставит в очередь вызовы к узлу NG, Кения продолжает работать. Переключение не помогает: на тех же кабелях идут и маршруты в Европу. Ждём восстановления связи и информируем покупателей через SMS-агрегатор внутри страны.

### S6. Отказ масштаба всей ЮАР (риск принят)

Основной регион и DR находятся в одной стране. Пока данные не разрешено вывозить из Африки, отказ всей ЮАР закрывается только кешем в приложении. Вероятность — 1 из 10 по FMEA (F-12). Триггер пересмотра — заключение юристов, разрешающее копии за пределами ЮАР: тогда добавляется копия бэкапов в ЕС (ADR-003, «Обратимость», сценарий 5).

## 4. Учения

| Учение | Частота | Критерий успеха |
|---|---|---|
| Отключение зоны (S1) | Ежемесячно на staging, раз в квартал на проде | ≤ 2 мин, 0 потерянных заказов |
| Переключение региона на AWS (S2) | До 01.10, далее раз в квартал | ≤ 4 ч, расхождение по сверке = 0 |
| Переключение узла NG на Абуджу (S3) | До 01.10, далее раз в квартал | ≤ 4 ч, распечатывание OpenBao ≤ 30 мин |

## Assumptions

- Держатели ключей OpenBao (3 из 5) доступны круглосуточно, хотя бы трое — в течение часа.
- Партнёры принимают оба набора исходящих IP: GCP и AWS.
- Layer3 даёт K8s в Абудже по запросу в течение часа. Если нет — держим там одну тёплую ВМ, +\$49/мес.
